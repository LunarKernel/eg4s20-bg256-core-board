## 遇到的问题

1. 直接生成 PDF 不满足需求，因为用户需要 Altium 原生 `.SchDoc`，并且其中器件必须可逐个编辑。
2. 直接修改 `.SchDoc` 的 OLE/CFB 二进制结构不可行，出现过以下问题：
   - 打开后空白。
   - Altium 打开后卡住。
   - 元件挤在左下角。
   - 页面中出现异常黄色大块区域。
3. Altium 脚本 API 在当前版本中部分方法不可用：
   - `AddFilter_All` 报 `Undeclared identifier`。
   - `MoveBy` 报 `Undeclared identifier`。
4. Altium 脚本编辑器存在缓存/旧缓冲区问题。磁盘文件已修改后，Altium 仍可能继续运行旧代码，需要关闭脚本标签页或重启 Altium 后重新打开 `.PrjScr`。
5. 工作区路径包含日文 `ドキュメント`，Altium 脚本解释器按非 UTF-8 编码读取时会把路径显示或解析为乱码，导致输出没有落到预期目录。
6. 原项目引用了 `01_Connectors.SchDoc`，但当前仓库中没有该源文件。PDF 第 1 页对应的连接器部分还不能直接从原生源图复制，需要后续重建或找回缺失源文件。

## 解决问题的经验

1. 对 Altium 原生 `.SchDoc`，优先使用 Altium 自身 API 创建和复制对象，不要直接拼接或重写二进制内容。
2. Altium 脚本报错后要先停止调试状态，否则无法关闭当前文档。
3. 修改脚本后必须确认 Altium 重新载入磁盘文件，必要时关闭脚本标签页并选择不保存旧缓冲区。
4. 对包含中文、日文或其他非 ASCII 字符的路径，Altium 脚本容易出现编码问题。当前准备改用纯英文临时路径运行脚本。
5. 失败产物需要从主工程目录隔离，保留在 `tmp` 便于排查，但不要提交到 GitHub。
